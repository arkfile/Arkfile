# Finish Auto Logout and Admin Access Tightening

## Status

This document tracks the work left over from `docs/wip/auto-logout.md` and `docs/wip/admin-sec.md`, and is the single plan for finishing both. Both plans are implemented on the server side: session families, the six-hour idle cap, the 24-hour cap with one-file grace, the 60-minute marked admin login, the Caddy 404 on admin and bootstrap paths, the direct-local-connection check, marked-login scope, and the admin re-registration routes. Local `dev-reset.sh` followed by `e2e-test.sh` passed.

The code is deployed to `test.arkfile.net` with `test-update.sh` and to `arkfile.net` with `prod-update.sh`. On 2026-11-11 a check from outside both servers returned 404 for `GET /api/admin/system/health` and `POST /api/bootstrap/register/response`, and 200 for `GET /api/admin-contacts`, so the public proxy no longer reaches admin or bootstrap routes. Still to confirm on each server: `arkfile-admin login` followed by a read-only admin command, and a normal browser sign-in that reaches the file list.

All open questions from the original plans are decided (see Decisions). What remains is the work list below. None of it requires an OPAQUE key rotation. As a precaution, do not run `rotate-opaque-keys` or flag an admin account on a real deployment until work item 2 has covered the admin re-registration ceremony.

## Decisions

Full access tokens without `family_id` are rejected immediately. The rule in `handlers/session_lifetime.go` that accepts such a token when its `iat` is before process start goes away now, not in a later release. `processStartedAt` resets on every restart, so the rule is a standing bypass of the idle and 24-hour checks for any still-valid token from the old binary, which matters most on self-hosted deployments with a long `JWT_TOKEN_LIFETIME_MINUTES`. No data is affected. An upgrading browser user signs in once more; `arkfile-client` recovers through refresh because the startup backfill already created family rows for existing refresh tokens.

`arkfile-client` refreshes an expired or nearly expired access token before a command, the same way `arkfile-admin` does, instead of rejecting it locally. The server still bounds the refresh token by the idle and 24-hour limits. This depends on the agent session binding following a refresh (work item 3), and on a file lock around read-refresh-write so two processes cannot present the same refresh token and trigger reuse revocation of every device.

A repeated upload complete succeeds. When the upload session is already `completed`, belongs to the caller, and the request carries the same `total_chunks`, `CompleteUpload` returns 200 with the stored `file_id`, `storage_id`, and `encrypted_stream_sha256` read from `file_metadata`, plus the current storage totals. It performs no storage, accounting, billing, or replication work. Every other non-`in_progress` status keeps today's 400. This fixes both clients without client changes and removes false failures on lossy links as well as during grace.

A marked admin login has a 15-minute idle limit inside the 60-minute cap. The admin notice is "admin session ended after 15 minutes without activity, please login again". The ended reason is `idle` and the error code is `session_idle`; the server and `arkfile-admin` choose the admin wording from the family's `login_kind`.

An admin export already streaming at the 60-minute mark gets no hard stop and no write deadline. The token cannot start a new request after the mark, the stream carries only one encrypted `.arkbackup` that the admin cannot decrypt, and a dropped connection already ends it.

## Findings

The `arkfile-client` agent session binding does not follow a refresh. The agent in `cmd/arkfile-client/agent.go` binds the cached Account Key and digest cache to `tokenHash`, the SHA-256 of the access token, and wipes all sensitive data when a request presents a different hash. `refreshSessionToken` never updates that binding. After any upload long enough to refresh mid-transfer, `AddDigest` runs with the new token and the agent silently wipes the Account Key; the next command fails and asks for a new login. This is an existing bug, and it blocks refresh-before-command.

`arkfile-client` has no file lock around refresh. `docs/wip/auto-logout.md` requires one; only `arkfile-admin` has it (`lockAdminSession`).

The `arkfile-client` raw transfer paths do not read the session error. On HTTP 401, `uploadChunk` and `doChunkedDownload` in `cmd/arkfile-client/commands.go` call `ensureFreshSessionToken(client, session, 0)`. A zero threshold becomes the 5-minute default, so a still-valid access token is not refreshed, the same token is retried, and the second 401 returns a generic `errAuthExpired` without reading the body. `exportOneBundle` in `cmd/arkfile-client/export.go` replaces the refresh result with `errAuthExpired`, so a `session_absolute` refresh reply is lost, and it never reads the first 401 body.

The `arkfile-client` download and export batches do not stop on a session error. `runOwnerDownloadBatch` aborts a round only on cancellation. After `clearExpiredLocalSession` empties the in-memory tokens, every remaining file fails on its metadata request and the user is prompted to retry. Only the upload batch adds the "other files in the queue were not uploaded" count, and no batch says whether the file in progress finished.

The browser download batch notice has the wrong wording and count. The only place that attaches the session code is `ensureFreshBatchAuth` in `client/static/js/src/files/download-batch.ts`, which runs between files. When it fires, the previous file has finished and the current one never started, but the notice says "The file in progress did not finish" and the queued count omits the current file. The upload and export batches never call `absoluteBatchNotice`.

The admin re-registration ceremony has no automated coverage: no unit tests for `AdminReregisterResponse` or `AdminReregisterFinalize` and no e2e case. A flagged admin can sign in again only through this ceremony on the server, so a bug in it would lock admins out with no web recovery path.

Several e2e cases from the original plans are missing: `arkfile-admin logout` followed by `session_logged_out` on the copied refresh token; `arkfile-admin force-logout` against the admin itself followed by 401 on the copied access token; an admin session file with `expires_at` in the past refreshing and succeeding; the refresh cookie `Max-Age` shrinking toward the 36-hour ceiling with `session_expires_at` constant; and two `arkfile-client` logins where logging out one leaves the other working.

`docs/api.md` does not list `/api/admin/reregister/response` or `/api/admin/reregister/finalize`, and its 409 description reads as if a flagged admin gets the public re-registration response. A flagged admin on the public login gets the generic failure. The OPAQUE rotation section of `docs/security.md` says the same, and it does not describe the Caddy 404, the direct-local-connection check, or that `arkfile-admin logout` ends that family on the server.

`models.CheckSessionFamily` is only called from tests. Production paths use `DecideSessionUse` through `AuthorizeSessionUse` and `ValidateRefreshSession`. Remove it and move its tests onto `DecideSessionUse`.

## Work list

Each item ends with `go test ./...` (CGO flags from `AGENTS.md`) and, for TypeScript, `bun` tests. The developer runs `dev-reset.sh`, `e2e-test.sh`, and `e2e-playwright.sh` after items that change server or client behavior. Items 1 through 3 are each a reasonable point to save progress.

1. Server session rules. In `handlers/session_lifetime.go`, delete the pre-start `iat` branch so a full token with no `family_id` always gets the 401; reset-tier tokens keep their audience exemption. Delete `processStartedAt` and `ProcessStartedAt()` from `auth/jwt.go`, and replace `TestSessionLifetimeMiddlewareAllowsPreUpgradeTokenOnly` with a test that rejects a family-less full token whatever its `iat`. Add `AdminSessionIdleLimit = 15 * time.Minute` in `models/session_limits.go` and use it in `DecideSessionUse` when `login_kind` is `admin`; `sessionErrorMessage` in `handlers/auth.go` returns the admin idle line for an admin family. Remove `CheckSessionFamily` and move its tests. Make `CompleteUpload` idempotent for a completed session as described under Decisions, with handler tests for the replay, a different owner, a different `total_chunks`, and a `failed` session.

2. Admin path coverage. Add handler unit tests for the admin re-registration routes, including refusal of an unmarked handoff token and refusal of admin accounts on `/api/opaque/reregister/*`. In `e2e-test.sh`, flag the dev admin with `flag-user-reregistration` late in the run (one account, no key rotation), complete the ceremony through `arkfile-admin login`, prove the new login works on admin routes, and prove the normal login cannot re-register that account. Add the admin logout, admin self force-logout, admin expired-token refresh, and admin 15-minute idle cases; the idle case uses `/api/admin/dev-test/sessions/shift` with a `family_id` on the admin's own family. In `cmd/arkfile-admin/session.go`, map `session_idle` to the admin idle line and `session_absolute` to the 60-minute line, and remove the session file when an ordinary admin command gets either code.

3. `arkfile-client` session handling. Add an agent method that takes the old and new token hashes, verifies the old one, and switches the binding without touching the key or TTL; call it from `refreshSessionToken` after a successful refresh. Add a file lock around read-refresh-write, matching `lockAdminSession`. Make `requireSession` refresh an expired or nearly expired access token instead of rejecting it, and update the e2e checks at the "Agent digest privacy and session enforcement" scenario to expect refresh and success. Add one helper that reads the JSON `error` from a 401 body and returns `errSessionIdle` or `errSessionAbsolute` after `clearExpiredLocalSession`, and use it in `uploadChunk`, `doChunkedDownload`, and `exportOneBundle`. Make the download and export batches stop on `errAuthExpired` as the upload batch does, and print whether the file in progress finished and how many queued files were not started, using the notice text in `docs/wip/auto-logout.md`. Unit tests follow `upload_batch_test.go` and `agent_test.go`.

4. Browser batch notices. In `download-batch.ts`, a refusal between files reports that the previous download finished and counts the current file as not started. Wire `absoluteBatchNotice` into the upload batch and the directory-picker export batch; native export reports only files not started. Tests go in `download-batch.test.ts`, `upload-batch.test.ts`, and `export-batch.test.ts`.

5. Remaining e2e cases and docs. Add the refresh cookie `Max-Age` and constant `session_expires_at` case and the two-login logout case to `e2e-test.sh`. Update `docs/api.md` (admin re-registration routes, flagged-admin generic failure, admin idle code, idempotent upload complete), `docs/security.md` (Caddy 404, direct-local-connection check, admin re-registration only through `arkfile-admin`, admin logout, 15-minute admin idle limit, no family-less tokens), and `docs/testing.md` (new cases). Update the session sections of `docs/wip/auto-logout.md` and `docs/wip/admin-sec.md` to match the decisions here, then archive all three plans.
